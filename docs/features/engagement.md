# Retention: push, background jobs, ranks, dashboard, notification preferences, weekly report

Feature reference split out of CLAUDE.md (2026-11-26). The cross-cutting rules in CLAUDE.md still apply here.

**Retention features (2026-11):**
- **Web Push** (`server/push.ts`, `client/src/lib/push.ts`, handlers at the bottom of `client/public/sw.js`). VAPID keys are generated on first boot and stored in the `settings` table under `vapid_keys` - **never delete or regenerate that row**, it would silently invalidate every subscriber. Table `push_subscriptions` (one row per browser, endpoint unique, dead endpoints removed on 404/410). Routes `/api/push/public-key|status|subscribe|unsubscribe`. Per-user activity (likes, comments, mentions, DMs) uses `sendPushToUserIfOffline` - no phone ping if the user has the site open (they already got the WS toast). Job stage changes always push to the client. **New smart links deliberately do NOT push** (owner decision 2026-11-25) - don't add a release broadcast there. SW only registers in production, so push can't be tested on the Vite dev server. iOS: only works for a site added to the home screen (`PushToggle` explains this).
- **Background jobs** (`server/engagement-jobs.ts`, 1-minute in-process tick, started after `initPush()`): game reminder push 10 min before open, challenge-deadline push the day before (after 12:00 Belgrade), hourly earned-rank upgrades. "Already sent" markers live in `settings` (`push_sent_game`, `push_sent_challenge_deadline`) so restarts can't double-send.
- **Game streak**: `storage.getGameStreak()` counts consecutive *challenge days* played (a day without a posted challenge can't break it; today's unplayed challenge doesn't break it either). Returned as `streak` on `GET /api/game/today` together with `challengeNumber` (#N). `ShareResultButton` (`components/game/`) draws a 1080x1920 story card (logo, #N, listens used, result, streak - **never the answer**) and shares via Web Share API, falling back to download.
- **Public artist pages** `/izvodjac/:username`: opt-in (`users.public_profile` + `users.bio`) from Podešavanja, verified artists only (`PATCH /api/me/public-profile` enforces it). `GET /api/public/artists/:username` returns a narrow shape (no id/email/role/click stats) with releases = smart links assigned to that user. Server-side og meta in `seo-meta.ts`. `/u/:username` (community profile) stays login-only - different page.
- **Monthly challenge**: `challenge_theme|description|prize|deadline` rows in `settings`, edited in the admin Projekti tab (`MonthlyChallengeForm` under the giveaway toggle). `GET /api/challenge` (public), `PUT /api/admin/challenge` (`requireRole("producer")`). A *new* theme pushes to all subscribers. Shown via `ChallengeBanner` on /giveaway and in the home "Za tebe danas" strip.
- **Earned rank** (`server/activity.ts`): points from real activity, weighted so it can't be spammed (posts/comments count per active day; only likes from other users; only approved projects). Thresholds VIP 150 / Legenda 600. Ranks only go up automatically and the `admin` rank is never touched. **Any manual rank pick in the admin Korisnici tab sets `users.rank_locked = true`** and the hourly job skips locked users (so a manual demotion sticks); the select's "Automatski (po bodovima)" option (`rank: "auto"`) unlocks and immediately sets the points-earned rank. Perks (`RANK_PERKS` in `activity.ts`, mirrored in `igra.tsx`'s `maxPlays`): game listens 3/4/5 and giveaway uploads per month 1/2/3 for Korisnik/VIP/Legenda - site-enforced only, never studio commitments or prices. Progress + perks table in `RankPanel` on the Dashboard (`GET /api/me/activity`), progress bar hidden when the rank is locked.
- **"Za tebe danas"** (`components/home/ForYouToday.tsx`): personal strip under the hero for verified users (game status/streak, active job stage, unread messages/notifications, active challenge, push opt-in). Each item renders only when it has something real; the whole strip hides when empty.
- **Dashboard layout (2026-11-26)**: no stat-tile row (it showed 0/0/0/0 for most users). Order: header (avatar, "Zdravo, <username>", Poruke + Podešavanja - no booking CTA, the navbar has one) → `GettingStarted` → "Danas" items → live panels (`MyJobsPanel`, `MySmartLinkPanel`, `RankPanel`) → Licence/Fakture **only if the user has any** → giveaway submissions ("Moje prijave na giveaway", the `projects` table) only if any. The "Danas" items come from `useForYouItems()` exported by `ForYouToday.tsx` (shared with the home strip; `includeJob: false` on the Dashboard because the job stepper is right there).
- **`GettingStarted`** (`components/dashboard/GettingStarted.tsx`, "Prvi koraci"): onboarding checklist - avatar, push (inline `enablePush()`, skipped when unsupported/denied), first Pogodi Pesmu game, first community post, and public artist profile for verified artists. Every tick is derived from real data, never self-reported; the game step is latched in localStorage (`onb_game_<id>`) because "played" can flip back. Hidden for good once complete (`onb_complete_<id>`) or dismissed (`onb_dismissed_<id>`). Settings has `#obavestenja` and `#javni-profil` anchors (scrolled to on mount) for its links.
- **Notification preferences**: `users.notification_prefs` (JSON, missing key = on); categories in `NOTIFICATION_CATEGORIES` (`shared/schema.ts`). Every push now carries a `category`; `sendPushToUser`/`sendPushToAll` skip opted-out users (`wantsNotification()` in `push.ts`). Pushes without a category always go out - give new pushes a category. UI: `NotificationPrefs` under `PushToggle` in Podešavanja (`#obavestenja`).
- **Weekly smart link report**: Monday 10:00 job emails owners with ≥1 unique visitor last week (`weeklySmartLinkReportEmail` in `email-templates.ts`, unique-per-IP numbers, honours the `weekly_report` preference) plus a push. `getSmartLinksByUserId` also returns `weekUnique`/`prevWeekUnique`, shown on `MySmartLinkPanel`.
