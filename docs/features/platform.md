# File uploads, email, Google OAuth

Feature reference split out of CLAUDE.md (2026-11-26). The cross-cutting rules in CLAUDE.md still apply here.

**File uploads:**
- Avatar/image uploads: `POST /api/upload/avatar` → Cloudinary (`server/cloudinary.ts`), fixed `user_${id}` public_id with face-crop transformation. **Avatar only** - never point another uploader at it (`EditableImage` used to, which overwrote the admin's avatar and made every CMS image share one face-cropped file).
- CMS images (`EditableImage`): `POST /api/upload/cms-image` (`requireAdmin`) → `uploadRawImageToCloudinary()`, `studioleflow/cms` folder, unique public_id.
- Message images: `POST /api/upload/message-image` → Cloudinary `studioleflow/messages` folder, unique `msg_${userId}_${timestamp}` public_id, via `uploadRawImageToCloudinary()` (no overwrite, no crop).
- Audio uploads: `POST /api/upload/audio` → Cloudinary, with `fileTypeFromBuffer` magic-bytes validation.
- Game clip: `POST /api/upload/game-clip` (admin) → Cloudinary `studioleflow/game-clips` folder.
- Smart link cover: `POST /api/upload/smart-link-cover` (`requireVerifiedEmail` — staff or an assigned link owner, see `docs/features/smart-links.md`) → Cloudinary `studioleflow/smart-links` folder.
- Post images: `POST /api/upload/post-image` → `uploadRawImageToCloudinary()` (no face-crop, no overwrite), `studioleflow/posts` folder. Use `uploadRawImageToCloudinary` not `uploadImageToCloudinary` — the latter applies face-crop and would corrupt post images.
- Chat audio: `POST /api/upload/message-audio` → `uploadAudioWithMeta()`, `studioleflow/messages-audio`, max 10MB (see community-messaging.md).
- Post audio: `POST /api/upload/post-audio` → `uploadAudioToCloudinary()`, `studioleflow/posts` folder.
- CMS media: multer to `attached_assets/temp/`, then moved to `attached_assets/`. **Note:** this path is ephemeral on Railway — CMS media uploads are lost on redeploy. Only `attached_assets/` files bundled at build time persist (they're baked into `dist/public/`). If persistent CMS media is needed, route through Cloudinary instead.
- Desktop app installer: `POST /api/admin/desktop-app/upload` (`requireAdmin`, uses `uploadLargeFile` — a separate 150MB-limit multer instance, not the shared 20MB `upload`) → `uploadRawFileToCloudinary()` (`resource_type: "raw"`, chunked via `upload_large`, for arbitrary binaries Cloudinary's image/video pipelines don't apply to) → `studioleflow/desktop-app` folder. The resulting URL is stored via the generic `settings` table (`storage.setSetting("desktop_app_download_url", url)`), not a dedicated column — read back via `GET /api/admin/desktop-app/download-url`. This is how the `desktop-admin/` Electron app's Setup .exe (see that section below) gets distributed without committing an ~80MB binary to git or requiring a code redeploy for every new build: Super Admin uploads the current installer once through the Settings tab (`DesktopAppSection` in `admin.tsx`), the "Preuzmi" button anywhere just links to whatever URL is on file.
  - **This Cloudinary account has a hard ~10MB "Maximum file size" restriction** (account-wide, not per-resource-type) that blocks the ~80MB installer outright — confirmed by ruling out transfer truncation (the full file arrives at the server intact) and by trying chunked upload, file-based `upload_large`, and both `resource_type: "raw"` and `"video"`, all rejected at the same cumulative-size checkpoint with `File size too large. Got 12582912. Maximum is 10485760.` from Cloudinary's API. Chunked upload only works around HTTP transfer timeouts, not an account-level stored-file-size cap — **no code-side fix bypasses this.** Before uploading anything over ~10MB through this route, raise the limit in the Cloudinary dashboard (Settings → Upload → Media upload restrictions, or check the account's plan tier).
  - **`POST /api/admin/desktop-app/set-url`** (`requireAdmin`) is the workaround used in practice while that Cloudinary limit stands: it writes an arbitrary `https://` URL straight into the same `desktop_app_download_url` setting, no file upload involved. The Settings tab's "ili nalepi eksterni link" field calls this. Current installer is hosted as a GitHub Release asset (`gh release create` on the public `leflowic/studio-leflow` repo — GitHub Releases have no practical size limit and the repo is public, so the asset URL is directly downloadable, no auth needed) rather than Cloudinary.
- All upload routes have `uploadRateLimiter` applied (30/hr). Avatar and message-image routes also validate magic bytes via `fileTypeFromBuffer`.
- **Any `multer.diskStorage` config must generate its own filename server-side** (e.g. `` `${Date.now()}-${randomBytes(8).toString('hex')}${ext}` ``) — never build it from the client-supplied `file.originalname` directly, even with a timestamp prefix. The CMS upload config (`multerUpload` in `routes.ts`) used to do exactly that, which is a path-traversal write (a crafted `originalname` containing `../` escapes the destination directory). It's also worth re-verifying actual file bytes via `fileTypeFromBuffer` after the disk write, since `fileFilter` only sees the client-claimed MIME type.

**Email:**
- Transactional: Resend SDK (`server/resend-client.ts`), from `noreply@mail.studioleflow.com`.
- Templates in `server/email-templates.ts` (redesigned 2026-11): light white card on a warm off-white page, left-aligned copy, small logo + "Studio LeFlow" wordmark (dark `leflow-logo.png`, swapped to `leflow-logo-white.png` under `prefers-color-scheme: dark`), anthracite button, darker-oak links. Every template passes a hidden `preheader` (inbox preview line) to `wrap()`. Keep the anti-slop rules here too: no dark hero banner, no letter-spaced caps labels, no gradient rules, no Title Case subjects/headings, no emoji, no SVG (Gmail strips it). Subjects are sentence case.
- **`sendEmail()` takes camelCase options** (`replyTo`, attachment `contentType`/`contentId`) - the Resend SDK maps them to the API's snake_case itself. The code used to pass `reply_to`, which the SDK silently dropped, so reply-to never worked before 2026-11-25. Contact-form notifications set `replyTo` to the visitor's email (hit Reply to answer them); license and delivery emails reply to podrska@.
- **Newsletter campaigns** (`POST /api/newsletter/send`) are wrapped in `newsletterCampaignEmail()` with a per-subscriber signed unsubscribe link (`/api/newsletter/u/<email b64url>/<hmac>`, HMAC keyed off `SESSION_SECRET`, no DB token) plus `List-Unsubscribe` + `List-Unsubscribe-Post: One-Click` headers (Gmail/Yahoo bulk-sender requirement). GET redirects to `/newsletter/odjava?status=...`, POST is the mail client's one-click. The path is in the maintenance allowlist.
- Business inbox: Zoho Mail at `podrska@studioleflow.com`.
- License auto-email: when admin assigns a user to a contract (`PATCH /api/admin/contracts/:id/assign-user`), the PDF is fetched and emailed automatically to the user's registered email. Email failure does not fail the request.
- **Railway blocks all outbound SMTP ports (25, 465, 587)** — Nodemailer/Zoho SMTP will always `ETIMEDOUT`. Never attempt direct SMTP from Railway; always use the Resend SDK. `server/zoho-client.ts` exists but is unused for this reason.
- Admin email composer: `POST /api/admin/send-email` (requireAdmin) uses `sendEmail()` from `resend-client.ts` with `replyTo: podrska@studioleflow.com`. Frontend: `client/src/components/admin/EmailTab.tsx`. The `customEmail()` template in `email-templates.ts` wraps plain text in the branded HTML layout.

**Google OAuth login/register:**
- `users.googleId` (nullable, unique) links an account to a Google `sub`. Password stays `NOT NULL` for Google-only accounts — `storage.createGoogleUser()` fills it with an unusable scrypt hash of random bytes (same `hash.salt` format as `hashPassword()`, kept local to `storage.ts` to avoid a circular import with `auth.ts`) so the column constraint holds without enabling password login until the user runs "forgot password".
- Flow: frontend uses `useGoogleLogin` from `@react-oauth/google` (implicit flow, popup) to get a Google `access_token` — **not** the GIS ID-token/credential flow, so the button can be fully custom-styled instead of Google's constrained iframe button. `GoogleAuthButton` in `auth-page.tsx` is the reference implementation (site's pill `Button`, `variant="outline"`, official multi-color G logo SVG).
- Backend `POST /api/auth/google` (`server/auth.ts`) takes `{ accessToken }` and **must** validate it before trusting it: call `https://oauth2.googleapis.com/tokeninfo?access_token=` and check `aud === process.env.GOOGLE_CLIENT_ID` (prevents an access token minted for a different Google app being replayed against this endpoint), then fetch profile from `https://www.googleapis.com/oauth2/v3/userinfo`. Never skip the `aud` check.
- Find-or-create order: `getUserByGoogleId(sub)` → if found, log in. Else `getUserByEmail` → if an existing password-based account matches, `linkGoogleAccount()` attaches the `googleId` and sets `emailVerified = true` (Google already verified the email, so this bypasses the normal pending-user verification flow). Else `createGoogleUser()` makes a brand-new user with a username auto-derived from the email local-part (`generateUniqueUsernameFromEmail`, collision-checked via `getUserByUsername`) and `termsAccepted: true` (clicking the Google button during registration is treated as acceptance).
- Response shape matches `/api/login` exactly (`{ ...userWithoutPassword, token }`) so `use-auth.tsx`'s `googleLoginMutation` reuses the same `setAuthToken` + `queryClient.setQueryData(["/api/user"], user)` pattern as `loginMutation`.
- Required env vars: `GOOGLE_CLIENT_ID` (server, for the `aud` check) and `VITE_GOOGLE_CLIENT_ID` (client, same value — Google client IDs are public by design) from a Google Cloud Console OAuth 2.0 Web client. No client secret is needed anywhere in this flow since it never exchanges an auth code.
- `App.tsx` wraps **only the auth pages** (`/prijava`, `/registracija`, `/auth`) in `MaybeGoogleOAuthProvider` (moved off the app root 2026-11-26: the provider loads Google's ~105KB GSI script, which was hitting every page). If another page ever needs Google sign-in, wrap that page too - `useGoogleLogin` outside the provider throws. — it renders `GoogleOAuthProvider` only when `VITE_GOOGLE_CLIENT_ID` is set, because `@react-oauth/google` **throws synchronously on mount with an empty clientId and crashes the whole app**. Same reason `GoogleAuthButton` is split into Configured/Unconfigured components: `useGoogleLogin` must never be called at all when unconfigured (it calls `initTokenClient` as soon as the GSI script loads, which throws on empty ID) — the unconfigured variant just shows a Serbian toast.
- **The server CSP must allowlist `https://accounts.google.com`** in `script-src`, `connect-src`, and `frame-src` (`server/index.ts` security-headers middleware). Without it the GSI script silently fails to load and clicking the Google button does nothing — no visible error, only a CSP violation in the console. This was a real production bug; don't remove those entries when touching the CSP.
